# 아기 맞이 웹페이지 운영 안내

빌드 없이 파일만 커밋하면 GitHub Pages에 반영됩니다. 반영까지 몇 분 걸릴 수 있고, 브라우저 캐시 때문에 최대 10분쯤 이전 내용이 보일 수 있습니다.

## 먼저 알아둘 것

- **공개 리포지토리입니다.** 사진 원본과 글, 잠긴 편지까지 리포에서 누구나 볼 수 있습니다. 검색 차단(`noindex`)은 노출을 줄일 뿐 막아 주지는 않습니다.
- **편지 잠금은 보안 기능이 아닙니다.** 화면에서 본문을 숨길 뿐이며, 파일은 리포와 URL로 읽을 수 있습니다.
- **체크리스트는 저장 기능이 없습니다.** 파일이 진실입니다. 상태를 바꾸려면 파일을 수정합니다.
- **`.nojekyll` 파일을 지우지 마세요.** 지우면 GitHub Pages가 마크다운을 변환해 사이트가 콘텐츠를 읽지 못합니다.

## 기록 추가

1. `content/posts/2026-11-02.md`를 만듭니다. 같은 날 두 번째 기록은 `2026-11-02-2.md`입니다.
2. `content/posts/index.json`에 파일명 한 줄을 추가합니다. **이 단계를 빠뜨리면 기록이 나타나지 않습니다.**

```json
["2026-11-02.md", "2026-11-02-2.md"]
```

기록 파일 예시입니다. 주차는 적지 않습니다. 날짜와 예정일로 자동 계산됩니다.

```markdown
---
date: 2026-11-02
title: 처음 들은 심장 소리
author: 아빠
photos: first.jpg, belly.jpg
---

본문을 씁니다.
```

`title`과 `photos`는 선택입니다. `author`는 `아빠` 또는 `엄마`로 적습니다.

**처음의 순간:** 기록에 `first: 첫 심장 소리`를 넣으면 "처음" 페이지에 모입니다. `첫 초음파`, `첫 심장 소리`, `첫 태동`은 채워지기 전까지 빈칸으로 보이고, 태어난 뒤에는 `첫 울음`, `첫 미소`, `첫 뒤집기`, `첫 걸음`이 더해집니다. 다른 이름을 적어도 됩니다.

**소리:** `audio: heart.m4a`를 넣고 파일을 사진과 같은 `images/날짜/` 폴더에 두면 기록에 재생기가 나타납니다.

**초음파 사진:** 인쇄된 사진에는 보통 이름, 생년월일, 병원명이 찍혀 있습니다. 공개 리포이니 그 부분을 잘라내고 올리세요. 나중에 지워도 리포 이력에 남습니다.

## 남편의 한 마디

`content/notes.json`에 항목을 추가하면 메인에 가장 최근 것이 보이고, 지난 것은 접혀서 쌓입니다. 날짜가 미래인 항목은 그날이 되어야 나타나므로 미리 써 둘 수 있습니다. `from`을 생략하면 "남편의 한 마디"로 표시됩니다.

```json
[
  { "date": "2026-11-03", "text": "오늘도 고마워요.", "from": "남편" }
]
```

## 사진

- `images/2026-11-02/`처럼 날짜별 폴더에 넣습니다.
- 긴 변 1600px 이하, 품질 80 JPEG를 권장합니다. 코드로 강제하지 않습니다.
- `photos`에 파일명만 적으면 기록 날짜의 폴더에서 찾습니다. 본문에 `![](images/2026-11-02/first.jpg)`처럼 써도 됩니다. 어느 쪽이든 썸네일 그리드로 모여 표시되고, 탭하면 원본을 봅니다.
- 파일명이 `belly.jpg`이면 기록 페이지의 "배 사진 시리즈"에 날짜순으로 모입니다. 해당 기록의 `photos`나 본문에 적어야 합니다.

## 일정 추가

`content/schedule.json`에 항목을 추가합니다. `time`과 `memo`는 선택입니다.

```json
[
  {
    "date": "2026-11-20",
    "time": "10:30",
    "title": "목덜미투명대 초음파",
    "kind": "검사",
    "memo": "남편 동행",
    "done": false
  }
]
```

- `kind`는 `검진`, `검사`, `행정`, `기타` 중 하나입니다.
- **병원에 물어볼 것:** `"questions": ["입덧약을 먹어도 되나요?", "다음 초음파는 언제인가요?"]`를 넣으면 그 일정 아래에 보입니다.
- 메인의 "다음 일정"은 완료되지 않은 가장 가까운 일정을 보여 주고, 당일이면 강조합니다.
- **검사 일정 안내:** 메인은 권장 시기 2주 전부터 끝날 때까지 "일정을 잡으세요" 안내를 띄웁니다. 다음 세 조건을 모두 만족하는 일정이 있으면 사라집니다.
  - `kind`가 권장 검사의 종류와 같습니다.
  - 일정 날짜가 권장 시기의 앞뒤 2주 안에 있습니다.
  - `title`에 검사명이나 키워드가 들어 있습니다. 검사명과 키워드는 `content/guide/`의 `tests` 항목에 있습니다.

## 편지

1. `content/letters/2026-11-05.md`나 `open-at-10.md`처럼 파일을 만듭니다.
2. `content/letters/index.json`에 파일명 한 줄을 추가합니다.

```markdown
---
date: 2026-11-05
author: 아빠
title: 처음 쓰는 편지
open: 10살
---

본문을 씁니다.
```

`open`에 적을 수 있는 값은 다음과 같습니다. 조건을 충족하기 전에는 제목과 작성일만 보입니다.

| 값 | 공개 시점 |
|---|---|
| `출생 전` | 항상 공개 (생략해도 같음) |
| `출생 후` | `birthDateTime` 입력 후 |
| `10살` | 출생일 기준 만 10세부터 |

## 예정일이 확정되면

`content/config.json`만 수정합니다.

```json
{
  "dueDate": "2027-06-25",
  "dueDateConfirmed": true
}
```

주차는 항상 `dueDate - 280일`로 계산하므로, 기존 기록의 주차 배지까지 자동으로 바뀝니다. `lmp`는 처음 기준값을 남겨 둔 기록이며, `dueDate`가 있으면 계산에 쓰이지 않습니다.

태명은 같은 파일의 `nickname`에 적습니다.

## 출생 후

1. `content/config.json`의 `birthDateTime`에 `"2027-06-20T14:30"` 형식으로 입력합니다. 메인이 출생 모드로 바뀌고 네비게이션에 탄생 페이지가 나타납니다.
2. `content/birth.md`에 그날의 이야기를 씁니다.

출생일 당일은 "생후 0일"입니다.

출생일을 입력하면 네비게이션에 "성장" 페이지도 나타납니다.

- **키와 몸무게:** `content/growth.json`에 잰 값을 추가하면 그래프로 그립니다. 값 하나만 있어도 됩니다. 또래와 비교하는 백분위는 넣지 않았습니다.

```json
[
  { "date": "2027-07-20", "heightCm": 54.2, "weightKg": 4.3 }
]
```

- **개월별 사진:** 기록 사진의 파일명을 `month.jpg`로 하면 개월별로 모입니다.
- **예방접종:** 맞은 뒤 `content/vaccines.json`의 해당 항목에 `"done": "2027-08-20"`을 추가합니다. 일정은 질병관리청 2026년 표 기준이니 태어난 뒤 최신 표와 대조해 주세요.

## 그 밖의 파일

| 파일 | 내용 |
|---|---|
| `content/names.md` | 이름 후보, 태명 이야기 |
| `content/capsule.md` | 타임캡슐 |
| `content/checklist.md` | 체크리스트. `- [ ]`와 `- [x]`로 표시 |
| `content/support.md` | 행정·지원 안내. 제도가 바뀌면 내용과 `reviewed` 날짜를 고칩니다 |
| `content/guide/NN.md` | 주차별 가이드. `우리 병원 메모` 칸은 내원 후 직접 채웁니다 |
| `assets/style.css` | 색과 폰트는 파일 맨 위 변수에 모여 있습니다 |

## 가이드 안내

가이드는 일반 정보이며 담당 의사의 안내가 항상 우선합니다. 각 카드의 출처와 마지막 검토일을 확인하고, `TODO: 병원 확인` 항목은 내원 때 확인해 채워 주세요.

## 디자인 바꾸기

색과 글꼴은 `assets/style.css` 맨 위의 변수에 모여 있습니다. 제목 글꼴은 고운바탕(Gowun Batang, SIL OFL 라이선스)이며 자주 쓰는 한글만 남겨 `assets/fonts/`에 넣었습니다. 드문 글자는 기본 글꼴로 보일 수 있습니다.

## 배포

`main` 브랜치 루트를 GitHub Pages로 배포합니다(Settings > Pages > Deploy from a branch). 별도 Actions는 필요 없습니다.
